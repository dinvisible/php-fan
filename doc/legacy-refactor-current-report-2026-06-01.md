# Отчет: остатки старого подхода и следующий DI-рефакторинг

Дата анализа: 2026-06-01

Область анализа: `_core`, `_project`, `htdocs`, `cli`; без `vendor` и `legacy_assets`.

## Краткий вывод

Проект уже сильно продвинут в сторону dependency injection: старые service-locator gateway, `::instance()`, `parse_ini_file()`, `call_user_func*` и прямой `eval()` в production-срезе не найдены. Основной оставшийся долг теперь не в массовых прямых вызовах native API, а в границах совместимости: static bootstrap/registry facade, ручная include/require-композиция, nullable fallback factories и legacy-доступ к request/session окружению.

## Что осталось от старого подхода

| Приоритет | Участок | Что осталось | Примеры файлов | Риск | Что рефакторить дальше |
|---:|---|---|---|---|---|
| 1 | Static bootstrap lifecycle | `bootstrap` остается главным static facade и владельцем static `$contextState`. State уже вынесен в `context_registry_state`, default state graph вынесен в `_core/bootstrap/context_registry_state_default_factory.php`, injected `setContext()` / `setContextFactory()` больше не создают default graph перед подменой state, `context_registry_state` больше не имеет mutable setters, bootstrap config loading вынесен из static `_setConfig()` в injectable `_core/bootstrap/bootstrap_config_loader.php`, а bootstrap error-handler setup вынесен из static `_setErrorHandler()` в `_core/bootstrap/bootstrap_error_handler_setup.php`. Но lifecycle все еще стартует через static API. | `_core/bootstrap.php`, `_core/bootstrap/context_registry_state.php`, `_core/bootstrap/context_registry_state_default_factory.php`, `_core/bootstrap/bootstrap_config_loader.php`, `_core/bootstrap/bootstrap_error_handler_setup.php`, `_core/bootstrap/context_registry_state_factory.php`, `_core/bootstrap/context.php`, `_core/bootstrap/state.php` | Средний | Выделить non-static application/bootstrap runner. `bootstrap` оставить тонкой compatibility-оболочкой для старых entrypoint-ов. |
| 2 | Static container registry bridge | `container_registry` уже стал тоньше, но все еще держит static `$state` и остается мостом от legacy-кода к container. Provider/state leaf factories получают dependencies явно. Normal bootstrap runtime создает registry state через `_core/bootstrap/container_registry_state_factory.php` и устанавливает его из `_core/factory/bootstrap/context_container_factory.php`; implicit default graph fallback удален. `container_registry::get()` без configured state теперь явно падает, а test-only `set()`, `setProvider()` и `setProviderFactory()` hooks сняты со static registry/state API. Registry больше не подгружает provider/state dependencies сам. | `_core/di/container_registry.php`, `_core/bootstrap/container_registry_state_factory.php`, `_core/factory/bootstrap/context_container_factory.php`, `_core/factory/bootstrap/context_defaults_factory.php`, `_core/di/container_registry_state.php`, `_core/di/container_registry_state_factory.php`, `_core/di/container_provider_factory.php` | Средний | Сужать оставшийся static facade API: normal code должен получать container/context через bootstrap/application objects, а `container_registry` оставить только для явной legacy/test injection. |
| 3 | Bootstrap factory self-defaults | Закрыто для bootstrap layer: `loader`, `runner`, `bootstrap_operations_factory`, `bootstrap_runtime_factory`, `context_registry_state_factory`, `context_factory`, `bootstrap_config_loader`, `bootstrap_error_handler_setup` и `context` получают default/boundary dependencies извне. Concrete default composition собрана отдельной default factory, а не размазана по state/context classes. | `_core/bootstrap/context.php`, `_core/factory/bootstrap/context_factory.php`, `_core/bootstrap/context_registry_state_factory.php`, `_core/bootstrap/context_registry_state_default_factory.php`, `_core/bootstrap/bootstrap_config_loader.php`, `_core/bootstrap/bootstrap_error_handler_setup.php` | Низкий | Дальше держать это правило тестами и переходить к self-defaults в DI factory layer. |
| 4 | Configured extension construction | Dynamic `new $className(...$arguments)` теперь один и находится в явном boundary. Это нормальный extension point, но internal/core services все еще частично проходят через общий configured boundary. | `_core/factory/configured_service_factory.php`, `_core/di/*_factory.php`, `_core/factory/bootstrap/context_defaults_factory.php` | Низкий-средний | Разделить internal typed factory map и plugin/config extension API. Dynamic construction оставить только для настоящих extension points. |
| 5 | Factory self-defaults | Закрыто: DI factories больше не принимают nullable `configuredServiceFactory` и не создают default `configured_service_factory` сами. | `_core/di/*_factory.php`, `_core/factory/application_container_factory.php` | Низкий | Держать configured boundary ownership только в `application_container_factory` / `context_defaults_factory` и source guards. |
| 6 | Manual include/require composition | Ручная загрузка файлов еще заметна: больше всего в `application_container_factory`, bootstrap/context defaults, loader, template/parser и installer entrypoints. | `_core/factory/application_container_factory.php`, `_core/bootstrap.php`, `_core/bootstrap/loader.php`, `_core/factory/bootstrap/context_defaults_factory.php`, `htdocs/install/index.php` | Низкий-средний | Закрепить allowlist: `require/include` допустимы только в entrypoints, bootstrap composition и file adapters; runtime services не должны подгружать файлы сами. |
| 7 | Request/session globals boundary | Прямой доступ к `$GLOBALS` и `$_SERVER` локализован, но legacy-модель request/session окружения еще сохраняется. | `_core/service/request_input.php`, `_core/service/session/adodb_session_globals.php`, `_core/service/request.php` | Средний | Оставить superglobals только в adapter-низу; выше прокидывать immutable request/session context через DI. |
| 8 | Native PHP side effects | Native calls уже в основном вынесены в adapters, но эти adapters остаются hard runtime boundaries: `header`, `setcookie`, `error_log`, `ini_get/ini_set`, error handlers, GD/image API. | `_core/adapter/header_writer.php`, `_core/adapter/cookie_writer.php`, `_core/adapter/error_log_writer.php`, `_core/bootstrap/php_runtime_settings.php`, `_core/adapter/warning_capture.php`, `_core/adapter/image_*` | Низкий | Сохранить как явный adapter layer, покрывать tests и не пускать native API обратно в services. |
| 9 | Template/meta/string-driven runtime | Template, block и meta layer все еще опираются на строковые правила, file discovery и runtime parsing. Это уже следующий слой после lifecycle/DI. | `_core/service/template/*`, `_core/block/**/*.meta.php`, `_project/**/*.meta.php`, `_core/bootstrap/loader.php` | Низкий-средний | После cleanup lifecycle выделить typed contracts для template/meta parsing и оставить legacy parsing как compatibility adapter. |

## Рекомендуемый порядок

| Шаг | Работа | Почему так |
|---:|---|---|
| 1 | Сузить static `container_registry` facade API | Implicit fallback удален; следующий долг - убрать зависимость normal/test paths от static `container_registry::get()` и передавать container/context явно. |
| 2 | Сузить `bootstrap` до compatibility facade | Bootstrap self-defaults закрыты; следующий слой - убрать сам static lifecycle owner. |
| 3 | Разбить `application_container_factory` на smaller composition roots | Leaf-level email default закрыт, но concrete defaults теперь еще сильнее сконцентрированы в central composition root. |
| 4 | Зафиксировать allowlist для `require/include`, superglobals и native API | Не дает старому подходу возвращаться в runtime services. |
| 5 | Отдельно заняться template/meta contracts | Это более рискованный слой, лучше идти туда после стабилизации lifecycle. |
