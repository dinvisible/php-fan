# Отчет: что осталось от старого подхода

Дата анализа: 2026-06-01

Область анализа: `core`, `project`, `htdocs`, `cli`; без `vendor` и `legacy_assets`.

## Краткий вывод

Проект уже сильно продвинут в сторону dependency injection. Старые service-locator gateway, `::instance()`, `parse_ini_file()`, `call_user_func*`, прямой `eval()` и большая часть native runtime side effects не найдены в обычном production-коде.

Главный оставшийся долг теперь не в отдельных вызовах `header()` или `error_log()`, а в архитектурных границах: static bootstrap facade, static compatibility registry, ручная include/require composition layer, request/session окружение через `$GLOBALS` и legacy template/meta parsing. Dynamic construction по имени класса сведена к одному явному boundary.

## Что еще осталось и что рефакторить дальше

| Приоритет | Участок | Что осталось от старого подхода | Примеры файлов | Риск | Что делать дальше |
|---:|---|---|---|---|---|
| 1 | Static bootstrap facade state | `bootstrap` остается static entrypoint и держит static `$contextState`, но default state creation уже вынесен в `core/bootstrap/context_registry_state_default_factory.php`, `context_registry_state` / injected facade setters больше не создают default context graph сами, сам `context_registry_state` больше не имеет mutable setters, config loading вынесен в injectable `core/bootstrap/bootstrap_config_loader.php`, а error-handler setup вынесен в `core/bootstrap/bootstrap_error_handler_setup.php`. | `core/bootstrap.php`, `core/bootstrap/context_registry_state.php`, `core/bootstrap/context_registry_state_default_factory.php`, `core/bootstrap/bootstrap_config_loader.php`, `core/bootstrap/bootstrap_error_handler_setup.php`, `core/bootstrap/context_registry_state_factory.php`, `core/bootstrap/context.php`, `core/factory/bootstrap/context_factory.php`, `core/bootstrap/state.php` | Средний | Переносить ownership context-state в non-static application/bootstrap runner; `bootstrap` оставить тонкой compatibility-оболочкой для entrypoint-ов. |
| 2 | Static compatibility registry | `container_registry` уже не хранит provider/providerFactory напрямую и больше не собирает default provider/container graph сам. Normal bootstrap path создает registry state через `core/bootstrap/container_registry_state_factory.php` и устанавливает его из `core/factory/bootstrap/context_container_factory.php`; implicit default graph fallback удален. `container_registry::get()` без configured state теперь явно падает, а test-only `set()`, `setProvider()` и `setProviderFactory()` hooks сняты со static registry/state API. Registry больше не подгружает provider/state dependencies сам. | `core/di/container_registry.php`, `core/bootstrap/container_registry_state_factory.php`, `core/factory/bootstrap/context_container_factory.php`, `core/factory/bootstrap/context_defaults_factory.php`, `core/di/container_registry_state.php`, `core/di/container_registry_state_factory.php`, `core/di/container_provider_factory.php` | Средний | Сужать static facade API: normal code должен получать container/context через bootstrap/application objects, а `container_registry` оставить только для явной legacy/test injection. |
| 3 | Configured extension construction | Dynamic `new $class` больше не разбросан по runtime: остался один общий `configured_service_factory`. `bootstrap_object_factory` теперь не создает его сам, а получает callable извне. Это нормальный extension boundary, но он все еще принимает class name из config/meta. | `core/factory/configured_service_factory.php`, `core/di/*_factory.php`, `core/factory/bootstrap/context_defaults_factory.php` | Низкий-средний | Классифицировать internal vs extension creation: internal services держать typed constructors/factory map, extension/plugin points оставить через общий configured boundary. |
| 4 | Manual include/require layer | Ручная загрузка файлов все еще нужна для bootstrap, loader, PHP-array storage, compiled templates, project tools и lazy fallback adapters. `loader` больше не создает `autoload_registration_error_logger` сам: logger теперь обязательная DI-зависимость, которую прокидывает bootstrap. `runner` больше не создает `error_demonstrator_factory` сам: demonstrator factory теперь обязательная DI-зависимость из container. `context_container_factory` больше не создает `application_container_factory` сам, а `error_handler_setup` и `initializer` больше не создают `php_runtime_settings`/`error_handler_registrar`: concrete defaults приходят из default composition layer/context. | `core/bootstrap.php`, `core/bootstrap/loader.php`, `core/bootstrap/runner.php`, `core/bootstrap/initializer.php`, `core/bootstrap/context.php`, `core/factory/bootstrap/context_defaults_factory.php`, `core/factory/bootstrap/context_container_factory.php`, `core/bootstrap/error_handler_setup.php`, `core/factory/application_container_factory.php`, `core/adapter/php_array_file.php`, `core/adapter/compiled_template_loader.php` | Низкий-средний | Закрепить allowlist: новые file-load cases оформлять только как adapters/factories; обычные services не должны делать `require/include` напрямую. |
| 5 | Raw request/session environment | Доступ к superglobals уже вынесен в boundaries, но сам подход `$GLOBALS`/session snapshot остается legacy-совместимостью. | `core/service/request_input.php`, `core/service/session/adodb_session_globals.php`, `core/service/request.php` | Средний | Ввести явные request/session abstractions для runtime-кода; `$GLOBALS` оставить только в самых нижних adapter-слоях. |
| 6 | Entrypoint side effects and globals | `bootstrap::init()` все еще определяет globals/constants, поднимает functions, loader, initializer и runner как static workflow; загрузка config уже вынесена в context-level `bootstrap_config_loader`, а bootstrap error-handler setup - в `bootstrap_error_handler_setup`. | `core/bootstrap.php`, `core/bootstrap/bootstrap_config_loader.php`, `core/bootstrap/bootstrap_error_handler_setup.php`, `htdocs/index.php`, `core/ini_cli.php`, `cli/install.php` | Средний | Выделить non-static application runner: entrypoint создает context/runtime объект и запускает его, а static facade вызывает runner ради совместимости. |
| 7 | Legacy template/meta parsing | В шаблонах и meta-слое остаются строковые правила, dynamic include markers и runtime parsing. Это не DI-блокер, но следующий слой модернизации после lifecycle. | `core/service/template/parser/base.php`, `core/block/root/html.php`, `core/block/**/*.meta.php`, `project/**/*.meta.php` | Низкий | После DI/lifecycle стабилизации выделить typed template/meta contracts и отдельные parsers/adapters с тестами на совместимость. |

## Рекомендуемый порядок

| Шаг | Работа | Почему сейчас |
|---:|---|---|
| 1 | Сузить static `container_registry` facade API | Implicit fallback удален; следующий долг - убрать зависимость normal/test paths от static `container_registry::get()` и передавать container/context явно. |
| 2 | Вынести ownership `bootstrap::$contextState` в non-static application/bootstrap runner | Direct static `context`/`contextFactory` уже убраны, default state factory вынесен отдельно; следующий слой - убрать сам facade как владельца lifecycle. |
| 3 | Разбить `application_container_factory` на smaller composition roots | Leaf-level email default закрыт; теперь concrete defaults стоит группировать по областям. |
| 4 | Ужесточить allowlist для include/require и raw environment access | Поддержит правило: side effects только в adapters/factories, business/runtime services через DI. |
| 5 | После lifecycle cleanup перейти к template/meta contracts | Это снизит строковую магию без риска ломать текущий DI-progress. |
